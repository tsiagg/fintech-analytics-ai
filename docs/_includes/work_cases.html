Financial analytics

Semantic layer and metric trust

Problem
The same commercial figure — net revenue, active users, withdrawal ratio — is easy to define differently in a dashboard, a chat answer and a report.
Approach
Compute each metric once in dbt, test the grain, and publish it through MetricFlow so every consumer reads the same definition.
What I built
Three semantic models and 57 metrics on tested marts, including the path from raw trades to net revenue.
Why it matters
The dashboard and the BI Assistant use different query paths. They cannot drift, because both resolve to the same intermediate model.

Governed AI

BI Assistant

{% if include.variant == "full" %} {% endif %}
Problem
Ad-hoc questions about warehouse numbers are useful. Letting a model write SQL against raw tables produces confident, plausible, wrong answers.
Approach
The model names metrics from an allowlist. MetricFlow executes. pandas does the arithmetic. Only then does an LLM see the numbers and write the prose.
What I built
A chat surface that returns a chart, a table and an explanation. Cheap questions stay on a fast model; anomaly and root-cause questions escalate. Neither model writes SQL.
Why it matters
Guardrails and cost routing without letting either model invent a business number.

Management reporting

AI CFO report

Problem
Leadership still needs a structured view of what happened when nobody typed a question.
Approach
Generate a fixed nine-section report on a schedule. Compute every quantitative element in Python first; the model only writes sentences around those facts.
What I built
An Airflow task that writes the HTML report to Postgres, and a page that renders the latest one.
Why it matters
A report worth reading needs deterministic inputs and a template, not a one-shot prompt.
